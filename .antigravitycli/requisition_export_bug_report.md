# รายงานการวิเคราะห์ระบบ: บั๊กการออกใบเบิก (Export Excel) หลังแก้ไขแบบร่าง

จากการตรวจสอบพฤติกรรมของระบบอย่างละเอียด ทั้งในโค้ดฝั่งเว็บพรีวิว (`preview/route.js`) โค้ดฝั่งออกไฟล์ Excel (`confirm-daily/route.js`) และข้อมูลแบบร่างในฐานข้อมูล (`production_requisition_preview_drafts`) พบสาเหตุของทั้ง **2 บั๊ก** ดังนี้ครับ

---

## 1. สาเหตุของปัญหา (Root Cause)

สาเหตุหลักมาจาก **"ความต่างของช่วงวันที่ในการดึงแผนผลิต"** ระหว่างตอนพรีวิวบนเว็บ กับ ตอนที่กดออกไฟล์ Excel ส่งผลให้ **Document Key (คีย์เอกสาร) เกิดความไม่ตรงกัน (Mismatch)**

### ลำดับขั้นตอนการเกิดปัญหา:
1. **บนเว็บพรีวิว (แสดงสัปดาห์):**
   * ระบบโหลดแผนผลิตของทั้งสัปดาห์ (เช่น `2026-08-24` ถึง `2026-08-30`) ทำให้มี **แผนผลิตหลัก (FG / Main Plan)** ของวันอื่นๆ ติดมาด้วย
   * ระบบนำแผนผลิตหลักเหล่านั้นมาดึงข้อมูล **Section ID (ส่วนงานผลิต)** เช่น `832C05C8-3E78-48F1-9C53-06BF01DC2955` และบันทึกเก็บไว้เป็นค่าเริ่มต้นสำหรับแผนกนั้นๆ (เรียกว่า `sectionByDept`)
   * สำหรับ **แผนผลิตย่อย (WIP / Sub Plan)** (ซึ่งในฐานข้อมูลจะไม่มีคอลัมน์ Section ตรงๆ) ระบบจะดึงแผนกของ WIP นั้นแล้วเอามาเทียบใน `sectionByDept` จนหา Section ID ที่ถูกต้องเจอ
   * คีย์ของใบเบิก (Document Key) จึงถูกสร้างขึ้นอย่างถูกต้อง เช่น:
     `[แผนกบิสกิต] | [ห้องปั้น/แต่งหน้า] | [SHIFT1] | SECTION:832C05C8-3E78-48F1-9C53-06BF01DC2955`
   * เมื่อผู้ใช้แก้ไขจำนวน ระบบจะบันทึกแบบร่าง (Draft) ลงฐานข้อมูลด้วยคีย์นี้

2. **ตอนกดออกไฟล์ Excel (ระบุวันเดียว - Daily Export):**
   * ฝั่ง Backend ของเมนูออก Excel จะระบุช่วงวันสั้นลง เหลือแค่วันเดียวที่เลือก (เช่น `2026-08-24` ถึง `2026-08-24`)
   * หากในวันที่เลือกนั้น **ไม่มีแผนผลิตหลัก (FG / Main Plan) ของแผนกนั้นอยู่เลย** (มีเฉพาะแผนผลิตย่อย WIP)
   * ระบบจะไม่สามารถสร้าง `sectionByDept` ของแผนกนั้นได้ ส่งผลให้การหา Section ID ล้มเหลวและเบนเข็มไปใช้ค่าเริ่มต้นคือ `"DEFAULT"`
   * คีย์ของใบเบิกในตอนออก Excel จึงถูกสร้างขึ้นมาเป็น:
     `[แผนกบิสกิต] | [ห้องปั้น/แต่งหน้า] | [SHIFT1] | SECTION:DEFAULT`

3. **ผลลัพธ์ที่ตามมา (เกิด 2 บั๊ก):**
   * **บั๊กที่ 1 (จำนวนไม่อัปเดต):** เมื่อคีย์ที่ระบบสร้างขึ้น (`SECTION:DEFAULT`) ไม่ตรงกับคีย์ที่อยู่ในแบบร่าง (`SECTION:832C05C8...`) ระบบจึงหาแบบร่างไม่เจอ (`draftPayload[doc.documentKey]` เป็น `undefined`) ส่งผลให้ข้ามการเขียนทับค่าแบบร่างไป และใช้จำนวนแผนตั้งต้น (10) แทนที่จะเป็นจำนวนที่แก้ไข (5)
   * **บั๊กที่ 2 (ขึ้นว่า "ไม่กำหนดห้อง"):** นอกจากนี้ หากแผนผลิตหลักของแผนกห้องนั้นไม่ถูกโหลดเข้ามาก่อนในลิสต์การหาเส้นทางผลิต (Routing) ฝั่ง Backend จะทำให้การจับคู่เส้นทางผลิตห้อง (Routing Component) ล้มเหลวไปด้วย ส่งผลให้ห้องผลิตในไฟล์ Excel แสดงผลเป็น `"ยังไม่กำหนดห้อง"` หรือ `"ไม่กำหนดห้อง"`

## 2. วิธีการแก้ไขที่แนะนำ (Recommended Fix)

เพื่อแก้ปัญหานี้อย่างถาวรและปลอดภัยที่สุด เราสามารถปรับโค้ดในไฟล์ [`confirm-daily/route.js`](file:///C:/Users/Riew/Desktop/KPF/Production-Line/Production-Line/src/app/api/production-planning/requisition/confirm-daily/route.js) ได้ดังนี้:

1. **ดึง Routing Components ของทุกแผนก:**
   ยกเลิกการฟิลเตอร์ `department_id` ในการดึงข้อมูล Routing Component หรือขยายให้ครอบคลุมแผนกต้นทางของวัตถุดิบทั้งหมด เพื่อการันตีว่าห้องผลิตจะถูกค้นพบเสมอ ไม่ว่าจะอยู่ในช่วงวันที่ใด
   ```javascript
   // แก้ไขใน C:\Users\Riew\Desktop\KPF\Production-Line\Production-Line\src\app\api\production-planning\requisition\confirm-daily\route.js
   const { data: routingRows, error: routingError } = await supabaseAdmin
     .from("production_routing_components")
     .select("id,department_id,parent_sku_code,component_sku_code,component_type,dispatch_split_mode,usage_type,issue_owner_department_id,work_center_id")
     // ลบ หรือ ปรับการฟิลเตอร์ตรงนี้ให้ดึงครอบคลุมมากขึ้น
     .is("deleted_at", null);
   ```

2. **ปรับปรุงการดึง Section Fallback:**
   แก้ไขให้การดึงแผนผลิตหลัก (`mainRows`) เพื่อใช้ทำ Fallback ของ Section ครอบคลุมทั้งช่วงกว้างเสมอ (ไม่ต้องฟิลเตอร์เฉพาะวันที่จะออกใบเบิก) หรือดึงจากรายการแผนผลิตทั้งหมดของแผนงานหลักนั้น เพื่อให้โครงสร้าง Section ID ตรงกับหน้าเว็บเสมอ

## 3. ขั้นตอนถัดไป

ขณะนี้ผมพบจุดเกิดเหตุและวิธีแก้ไขแล้ว (ยังไม่ได้ลงมือแก้ไขโค้ดตามความประสงค์ของคุณ) 
คุณสามารถตรวจสอบความถูกต้อง และตอบกลับมาในแชทนี้เพื่อสั่งให้ผมดำเนินการแก้ไขโค้ดต่อไปได้เลยครับ
