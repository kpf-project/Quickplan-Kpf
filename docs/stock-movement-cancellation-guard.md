# การป้องกันยอดเคลื่อนไหวผิดจากการยกเลิกเบิก

## การแก้ไข 2026-09-07

- API ยกเลิกเบิกตรวจประวัติรับคืน/ของเสียที่อ้างอิง sourceIssueItemId ก่อนเรียก RPC เดิม หากตรวจไม่ได้จะไม่อนุญาตให้ยกเลิก

- รายงานเก็บยอดยกมาและคงเหลือติดลบตามจริง ไม่เปลี่ยนเป็นศูนย์ พร้อมคำเตือนบนหน้ารายงาน ไม่เปลี่ยนสูตรบันทึกน้ำหนักหรือสร้างบาร์โค้ด
- Migration `20260907030917_guard_stock_issue_cancellation_children.sql` เพิ่ม trigger กันการยกเลิกที่ฐานข้อมูล ไม่แก้ข้อมูลย้อนหลัง ติดตั้งเมื่อ 2026-09-07 และทดสอบพฤติกรรมกับตารางชั่วคราวแล้ว

## ก่อนเปิดใช้จริง

1. ทดสอบ migration ในฐานข้อมูลทดสอบ: ยกเลิกเบิกที่ไม่มีรายการลูกต้องสำเร็จ; มีรับคืนหรือของเสียต้องถูกปฏิเสธและไม่มีการเปลี่ยนข้อมูลบางส่วน (ผ่านแล้วด้วยตารางชั่วคราวและ rollback)
2. ทดสอบยกเลิกพร้อมกับรับคืน/ของเสียด้วยสอง connection ทั้งสองลำดับ และตรวจว่าไม่มีรายการลูกที่อ้างถึงเบิกที่ถูกยกเลิก
3. ตรวจรายการ migration ค้างก่อนนำขึ้นจริง ห้าม push migration อื่นที่ยังไม่ได้ตรวจโดยรวม
4. Deploy แอปและ migration ที่ตรวจแล้ว จากนั้นตรวจรายงานและกรณีเบิกปกติซ้ำ
