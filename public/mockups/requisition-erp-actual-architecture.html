Enterprise Planning & ERP Synchronization Architecture

แผนผังสถาปัตยกรรมระบบใบเบิก: การคำนวณ WIP, เปลือก LOT และการผูกยอดจริงจาก ERP

แสดงกลไกตั้งแต่การแตกความต้องการวัตถุดิบ (BOM Explosion) การจัดการนโยบาย WIP/เปลือกแครกเกอร์ ไปจนถึงการซิงค์ข้อมูลจริง (Trade Code, Actual Qty, LOT & คลัง) จาก ERP โดยละเอียด

1. WIP & SHELL HANDLING

การจัดการ WIP และเปลือกแครกเกอร์

ในระบบใบเบิก วัตถุดิบประเภท WIP ถูกควบคุมโดยนโยบาย production_wip_policies:

  • เปลือกแครกเกอร์ (WKB-0002, WKB-0048): มีสถานะเป็นผลผลิตจากการอบในไลน์แผนกบิสกิต ไม่ต้องขอเบิกจากคลัง ระบบจะตัดข้ามใบเบิกเพื่อไม่ให้เกิดการเบิกซ้ำซ้อน
  • แป้งสาลีหมัก / ไส้สูตร (WK-2202, WK-1023): ถูกตั้งค่าเป็น requires_requisition: true ระบบจะนำเข้าสู่ใบเบิกเพื่อสั่งเบิกวัตถุดิบต้นน้ำจากคลังอย่างถูกต้อง

2. DOCUMENT KEY DISCRIMINATION

การแบ่งห้องและป้องกันการชนข้ามส่วนงาน

ระบบสร้าง Key เฉพาะเจาะจงระดับ 7 มิติใน buildDailyDocumentKey:

  • 7 มิติในการแยกใบ: Department, Room, Shift, Discriminator (Parent SKU / Workstream), Material Group (RAW/PACK) และ Work Date
  • การแยก RAW / PACK: ในห้องตีแป้งบิสกิต (BIS01) หรือห้องป้ายแยม (BIS03) รายการแป้งและน้ำตาลจะถูกแยกหมวดชัดเจน ไม่ปะปนกับบรรจุภัณฑ์

3. ERP ACTUAL & LOT OVERRIDE

การซิงค์ยอดจริงและ LOT จาก ERP

เมื่อผู้ใช้ยืนยันการผูกเลขเอกสาร ERP (X6910/...):

  • ดึงตรงจาก MSSQL: Gateway ดึงข้อมูล Trade Code (TRD_SH_CODE) และจำนวนจริง (TRD_QTY)
  • แสดงเลข LOT แท้: ดึง TRD_LOT_NO พร้อมรหัสคลัง (WL_CODE) แสดงเป็นแถว └ LOT ... กำกับแท็ก ERP สีเขียว แทนที่ยอดประมาณการเดิมทันที
